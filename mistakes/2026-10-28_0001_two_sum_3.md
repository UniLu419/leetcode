# 1. Two Sum

- 日期: 2026-10-28
- 题目: 0001_two_sum
- 类别: 思路

## 错在哪

第 19 行报 `TypeError: object of type 'NoneType' has no len()` 之后，第 2 版在第 12 行加了 `and hash_table[nums[i]] is not None`，想在用之前把 None 挡掉。但这个 None 不是本来就有的，是第 13 行把 `append` 的返回值赋回去造成的：

- 源头没改，所以第 19 行照样拿到 None，[3,3] 和 [0,4,3,0] 还是报同样的错。
- 这个判断还会让程序在遇到 None 时走进 else，把这个值已经存的下标列表直接换成 `[i]`。比如 [1,1,1,7] 跑完，表里 1 只剩 `[2]`，下标 0 和 1 都丢了。

## 正确写法

不在用的地方挡 None，去改产生 None 的那一行（第 12 行保持 `if nums[i] in hash_table:` 就够了）：

```python
hash_table[nums[i]].append(i)
```

## 知识点

- 报错的那一行是"用到坏值"的地方，不一定是"产生坏值"的地方。看到 `NoneType` 相关的报错，先倒推这个变量最后一次是在哪里被赋值的。
- 倒推的办法：在可疑的赋值后面临时加 `print(...)` 或 `assert x is not None`，第一个出问题的位置就是源头。
- 一个本不该是 None 的值变成了 None，加 `is not None` 判断只是把症状藏起来：报错可能消失，但数据已经错了，最后变成更难查的"答案不对"。
