# 332. Reconstruct Itinerary

- 链接: https://leetcode.com/problems/reconstruct-itinerary/
- 难度: Hard
- 最优解:

## 题型
图 · DFS · 排序

## 识别信号
- 每张机票恰好用一次、要把所有机票串成一条路线：把机场当点、机票当有向边，就是"每条边恰好走一次"的一笔画问题（欧拉路径）
- 题目保证一定存在合法路线，并要求多解时取字典序最小，提示出边要按目的地排序后依次尝试

## 解题步骤
记 E = len(tickets)，V = 机场个数。
1. 暴力：从 JFK 出发回溯，每个机场按字典序依次尝试还没用过的机票，用完全部 E 张就返回；第一条走通的路线就是字典序最小的答案。建图排序 O(E log E)，但遇到死路要撤销重来，最坏是指数级
2. 瓶颈：按字典序贪心地走，可能先走进一条提前走不动的死路（例如从 JFK 先飞字典序更小的 KUL，却再也回不来），回溯就是在反复撤销这些死路
3. 优化：Hierholzer 算法。邻接表按目的地排序；从 JFK 开始 DFS，每走一条边就把它从邻接表里删掉；一个机场的出边全部用完、无路可走时，才把它加入结果列表（后序）；最后把结果列表反转。每条边只走一次，不需要撤销，DFS O(E)，加上排序共 O(E log E)
4. 细节：用栈代替递归；邻接表倒序排好后每次从末尾 pop，取到的就是字典序最小的目的地，删除是 O(1)

## 关键一步
在一个机场"走不动了"才把它记入路线（后序），再整体反转：先被卡住的死路分支会排在路线最后，所以按字典序贪心走也不会出错，不需要回溯。

## 易错点
- 机票可能重复（同一起点终点出现多次），每张都要用一次，不能用 set 存目的地
- 起点固定是 JFK，不是字典序最小的机场
- 结果是后序收集的，最后一定要反转
- 先序记录路径（走到就记）配合字典序贪心会在死路上出错，例如 [JFK→KUL, JFK→NRT, NRT→JFK] 的答案是 JFK, NRT, JFK, KUL
- 某个机场可能只出现在终点、没有出边，取邻接表时要用 defaultdict 或 get 防止 KeyError
