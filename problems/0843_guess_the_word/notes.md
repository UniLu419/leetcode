# 843. Guess the Word

- 链接: https://leetcode.com/problems/guess-the-word/
- 难度: Hard
- 最优解:

## 题型
贪心 · 哈希计数

## 识别信号
- 交互题：只能通过 master.guess 得到"位置和字母都相同的个数"，猜测次数有上限
- 每次反馈只能把候选单词分成几组，要在最坏情况下也尽快缩小范围，提示每一步挑一个让"最坏情况剩余最少"的单词去猜

## 解题步骤
记 n = len(words)，L = 6 为单词长度，match(a, b) = a 和 b 位置相同且字母相同的个数。
1. 暴力：按列表顺序逐个猜，最坏要猜 n 次（100 次），远超 allowedGuesses
2. 瓶颈：每次猜测的反馈没有被利用。秘密单词 s 满足 match(猜测词, s) == 反馈值，和猜测词的 match 不等于反馈值的候选都不可能是答案
3. 优化一：维护候选列表，每次猜候选中的一个词，拿到反馈 r 后只保留 match(c, 猜测词) == r 的候选。每轮 O(n·L)。但如果总猜列表里第一个候选，碰上随机单词时反馈几乎总是 0，一次只能排除少数单词，仍可能超过次数
4. 优化二（极小化极大）：对每个候选词 w，统计它和所有候选的 match 值各出现多少次（按 0..6 分组计数），最大那组的大小就是"猜 w 后最坏还剩多少个"；选这个值最小的 w 去猜，再按反馈过滤。每轮 O(n²·L)，总共 O(n²·L·猜测次数)，n ≤ 100 很快

## 关键一步
猜之前先算"猜这个词最坏会剩几个候选"：用 match 值把当前候选分组，选最大组最小的词，这样无论反馈是什么，候选都缩得尽量快。

## 易错点
- 函数没有返回值，结果靠在次数上限内调用 master.guess(secret) 判定；超过 allowedGuesses 次调用（包括找到之后多余的调用）都算失败
- 函数拿不到 allowedGuesses（10 到 30），不能写死 for _ in range(10)，要一直猜到反馈等于 6 为止
- 过滤候选时要把刚猜过的词去掉，否则可能重复猜同一个词
- 随机单词两两之间大多 match 为 0，"猜 0 组最小"的词通常就是最优选择；只猜列表里的第一个候选在大数据下会超次数
- 猜不在 words 里的词返回 -1，同样消耗一次次数
